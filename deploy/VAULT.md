# 개인 보관함 복구

운영 media.env의 MEDIA_VAULT_BUCKET에 비공개 서울 버킷을 설정한다. VM 서비스 계정은 이 버킷의 객체만 읽고 쓴다. 앱이 선택본과 참여 계정의 인증 해시, 동의·접근 기록을 전송한 뒤 SAVED를 확정한다. 기존 SAVED는 기동 후 동기화된다. 원본, 전사, 미선택 편집본과 개인 토큰은 제외한다. 철회 시 revoked/{tripId}를 먼저 남긴 뒤 활성 객체를 삭제한다. 버킷 기본 soft delete 보존기간에는 관리자 복구용 객체가 남는다.

복원은 이전 서비스의 쓰기를 중단한 유지보수 구간에서 실행한다. 새 디렉터리만 허용한다. 버킷의 현재 철회 기록을 보존한다. 과거 버킷 상태를 통째로 승격하면 철회가 되돌아갈 수 있다.

```sh
python3 /app/media/vault.py restore "$MEDIA_VAULT_BUCKET" /data/library/restored-private
```

복원 도구는 파일별 SHA-256을 확인한다. 테스트 운행 하나만 복원할 때는 마지막 인자로 tripId를 준다. 복원본을 격리된 앱의 library/private에 연결해 기존 개인 토큰의 목록·재생과 타인 차단을 확인한다. 전체 복원 시 검증 뒤 정지된 앱의 private 경로로 승격하고 서비스를 시작한다. 빈 디렉터리에 보관함만 복원되며 진행 중 운행은 복원 대상에서 제외한다.
