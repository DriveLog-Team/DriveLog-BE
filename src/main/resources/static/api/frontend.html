개인 운행 시작과 동의

팀 BFF는 로그인한 사용자별로 POST /api/accounts를 호출해 반환된 accountId와 accessToken을 서버에서 안전하게 보관한다. 이후에는 같은 자격증명을 사용한다. 사용자 요청의 계정 ID를 그대로 믿지 말고 로그인 세션에 연결한 개인 토큰을 선택한다. Swagger의 Authorize에서 운영자 작업은 operatorToken, 개인 작업은 personToken을 사용한다. 하나의 요청에 Bearer 헤더는 하나다.

차량은 운행 UUID와 탑승자 명단, 정차 정보를 먼저 등록한다. 전원 동의가 끝나 UPLOAD가 되면 소유자 개인 토큰으로 전·후방 원본을 각각 전송한다.

POST /api/private-trips      (팀 서버)
{"sourceId":"운행 UUID","source":{"gear":"P","stationary":true,"audioSource":"front","frontOffsetMs":0,"rearOffsetMs":0,"roadReviewed":true},"owner":"소유자 계정 UUID","occupants":[
  {"occupant":"소유자 UUID","under14":false},
  {"occupant":"아동 UUID","under14":true,"guardian":"지정 보호자 UUID"}]}

신뢰된 등록 주체가 현장에서 확인한 좌석 순서·연령 구분·보호자 관계를 연결한다. 운행의 인원수와 연령 구분은 등록된 원본 명세와 일치해야 한다. 보호자 신분 확인은 등록 주체의 절차다. 응답의 tripId는 이후 모든 개인 운행 작업에 사용한다.

GET /api/private-trips                            (각 개인)
GET /api/private-trips/{id}                       (탑승자·지정 보호자)
PUT /api/private-trips/{id}/consents/{occupant}/PASSENGER  (탑승자 본인)
PUT /api/private-trips/{id}/consents/{occupant}/GUARDIAN   (지정 보호자)
{"extraction":true,"geminiTranscript":true}

동의 화면에는 원음 전사, 후보 전사문을 Gemini에 보내는 목적, 최종본 저장과 원본 삭제를 표시한다. 성인·아동은 각자 PASSENGER에, 지정 보호자는 아동의 GUARDIAN에 응답한다. 하나라도 거절하거나 철회하면 폐기를 시작한다. 전원이 동의하면 PENDING → UPLOAD가 된다. PUT /api/private-trips/{id}/media/{side}에 front·rear 파일을 각각 video/mp4로 보낸다. Content-Length와 X-Content-SHA256을 포함한다. 동일 해시 재전송은 안전하다. 두 파일이 검증되면 READY가 된다. 그 뒤 소유자 개인 토큰으로 아래의 POST /api/media/jobs에 개인 tripId를 보내고 편집한다. 미동의 403, 주행 중·도로 검토 미완료 409, 다른 계정의 보관 영상 접근은 404다.

편집 확정과 보관함

POST /api/private-trips/{id}/finalize
{"jobId":"선택한 READY 작업 UUID","moment":"moment-002"}
GET /api/library                      → 본인의 저장 목록
GET /api/library/{id}/clip            → 보관 MP4 (Range 지원)
POST /api/library/{id}/handoffs       → 휴대폰 저장용 일회 QR
DELETE /api/private-trips/{id}        → 저장 없이 종료 또는 저장본 삭제

마지막 편집 결과의 jobId와 카드 id를 보내면 선택한 MP4 한 개를 보관한다. SAVED 응답은 이 운행의 서버 원본 폴더·전사 중간물·이전 편집 버전까지 삭제가 끝났음을 뜻한다. 같은 선택으로 다시 확정할 수 있다. 다른 선택이나 진행 중인 작업이 있으면 409다. 확정 후 미리보기와 QR은 보관함 경로에서 발급한다. DISCARDING은 실행 작업이 종료되기를 기다리는 중이며 DISCARDED가 완료다. 보관함과 동의 기록은 서버 재시작 뒤에도 유지된다. 이미 받은 외부 파일, 차량에 남은 자료, 외부 AI의 데이터 보관은 이 서버의 파기 범위 밖이다.

1. 프론트 연결

먼저 배포 상태로 연결을 확인한다. 합성 운행 demo는 팀 작업공간을 사용한다. FE 서버(BFF)가 팀 사용자 인증 뒤 허용된 메서드와 경로만 프록시하고, Authorization: Bearer <MEDIA_TOKEN>을 주입한다. 토큰은 공개 번들·저장소·쿼리 문자열에 넣지 않는다. 개발자 개인 시험은 HTTPS Swagger의 Authorize를 사용한다. 팀 서버의 운영자가 IAP로 VM의 /opt/drivelog/media.env에서 MEDIA_TOKEN 항목만 받아 비밀 환경변수로 설정한다. Gemini 키는 FE에서 필요 없다.

Swagger는 같은 출처에서 호출한다. 별도 웹 출처에서는 브라우저가 자체 BFF를 호출한다. 팀 데모는 사전 등록된 합성 운행 demo로 시작한다. QR을 받은 휴대폰에는 팀 토큰이 필요 없다.

2. 실제 호출 순서

  1. GET /api/trips에서 ID를 선택하고 추천을 요청한다. 202는 등록 성공이다.
POST /api/media/jobs
Content-Type: application/json
{"tripId":"demo","profile":"STORY_15"}

→ 202 {"jobId":"…"}
GET /api/media/jobs/{jobId}

1~3초 간격으로 조회하고 화면 이탈·READY·FAILED 시 멈춘다. READY면 result.cards의 서버 순서를 사용한다. 각 카드의 title, recommendation.quote, recommendation.reason, cues를 표시한다. 예시 식별자 대신 실제 응답의 id를 사용한다. 카드의 시각은 모두 운행 시작 기준 ms다. 플레이어의 자막 시각은 (cue.startMs - card.startMs) / 1000초다.

GET /api/media/jobs/{jobId}/clips/{moment}
POST /api/media/jobs/{jobId}/edits
Content-Type: application/json
{"id":"moment-002","title":"다시 듣고 싶은 말"}

→ 202 {"jobId":"새 편집 작업 ID"}

편집은 제목·자막·구간 중 바꿀 필드만 보낸다. 제목은 1~80자, captions는 기존 발화와 같은 개수·순서의 문자열(각 200자 이하), startMs/endMs는 선택한 카드 안의 구간이다. 새 ID로 조회해 READY가 된 뒤 새 ID로 미리보기와 QR을 발급한다. 원본과 편집본은 다른 버전이다.

POST /api/media/jobs/{새 jobId}/clips/{moment}/handoffs
→ 201 {"id":"…","expiresAt":"…Z","qrImage":"data:image/png;base64,…"}

img.src = ticket.qrImage로 표시한다. 휴대폰 스캔 → 저장 확인 페이지 → ‘MP4 내려받기’ 순이다. 스캔만으로는 소진되지 않으며, 저장 요청 한 번에만 파일을 준다. 사용·만료·회수·다운로드 중단 후에는 재발급한다. 5분 만료, QR 이미지·코드는 로그에 기록하지 않는다. 카드 미리보기는 BFF에서 Range 요청과 206 응답을 그대로 전달한다.

4. 화면 상태와 복구

QUEUED → RUNNING → READY 또는 FAILED. READY여도 NO_SPEECH_CANDIDATE면 인식 발화 없음, NO_MEMORY_CANDIDATE면 선정된 구간 없음이다. 빈 카드를 오류로 표시하지 않는다. FAILED는 재시도 동작을 제공한다. 중복 작업은 같은 입력의 완성본을 재사용할 수 있다.

400 입력 수정 · 401 서버 토큰과 HTTPS 점검 · 403 탑승자/보호자/전사문 제공 등 해당 동의 확인 · 404 운행·카드·작업 다시 조회 · 409 정차/P단·도로 검토·기준 버전 확인 · 410 QR 재발급 · 416 Range 재요청 · 429 대기열이 비면 재시도 · 507 저장공간 확인. 작업 ID와 QR은 프로세스 메모리에 있어 서버 재시작 후 새 작업 요청이 필요하다. 작업 ID는 최근 최대 64개, 미사용 QR은 최대 128개다.

5. 도로 영상 보호

새 작업은 전·후방 영상을 서버 안에서 100ms마다 검사한다. 검출된 얼굴·번호판 주변을 넓혀 해당 카메라 화면에만 블러를 적용한다. 한쪽이라도 가까운 보행자를 검출하면 앞뒤 600ms를 더해 두 영상과 원음을 함께 제외한다. 제외 음성은 전사·Gemini 추천에 쓰지 않으며 편집으로 복원할 수 없다. 영상 프레임을 Gemini에 보내지 않는다.

기존 작업 등록·조회·편집 API를 그대로 사용한다. 운행 등록 시 "roadReview":{"complete":true}로 자동 검사를 사용한다. 기존 수동 nearPedestrian·blur 구간은 있으면 추가로 적용한다. 미검토 상태는 409다. 검사 실패는 FAILED로 끝나며 미처리 MP4로 대체하지 않는다.

GET /api/media/jobs/{id}의 READY 응답에서 result.privacy를 읽는다. cameras.front와 rear의 samples는 검사한 프레임 수, faceHits·plateHits·nearHits는 반복 검출을 포함한 건수다. excluded는 운행 시작 기준 밀리초의 반열린 구간이다. 예: [{"startMs":2400,"endMs":4600}]이면 해당 시간은 편집 타임라인에서 선택할 수 없다. 남는 발화가 없으면 cards는 빈 배열이다. 과거 저장본은 소급 처리되지 않는다.

근접 판정은 화면에서 사람이 차지하는 높이와 하단 위치 기준이며 실제 거리 측정값이 아니다. 야간·가림·빠른 움직임이나 작은 한국 번호판은 놓칠 수 있다. 공유 전 편집 영상을 확인한다.

6. 기획 범위와 남은 작업

실차 카메라 자동 수신, 실차 탑승자 신원·법정대리인 관계 확인, 차량·외부 서비스의 파기 확인, SNS 작성기는 별도 과제다. 글레오의 대화 추천 역할은 Gemini로 시연한다. 팀 작업공간에는 실제 승객 음성이나 영상을 등록하지 않는다.
