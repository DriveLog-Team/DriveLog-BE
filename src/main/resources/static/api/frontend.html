대화 추천에서 휴대폰 저장까지

운영 기준 주소 https://35.216.33.209 · 운영 Swagger · OpenAPI JSON. API 경로는 모두 /api/로 시작한다.

연결호출 순서전체 명세오류·상태기획 범위

1. 프론트 연결

먼저 배포 상태로 연결을 확인한다. 운행 및 편집 작업은 팀 작업공간을 공유한다. FE 서버(BFF)가 팀 사용자 인증 뒤 허용된 메서드와 경로만 프록시하고, Authorization: Bearer <MEDIA_TOKEN>을 주입한다. 토큰은 공개 번들·저장소·쿼리 문자열에 넣지 않는다. 개발자 개인 시험은 HTTPS Swagger의 Authorize를 사용한다. 팀 서버의 운영자가 IAP로 VM의 /opt/drivelog/media.env에서 MEDIA_TOKEN 항목만 받아 비밀 환경변수로 설정한다. Gemini 키는 FE에서 필요 없다.

Swagger는 같은 출처에서 호출한다. 별도 웹 출처에서는 브라우저가 자체 BFF를 호출한다. 팀 데모는 사전 등록된 합성 운행 demo로 시작한다. QR을 받은 휴대폰에는 팀 토큰이 필요 없다.

2. 실제 호출 순서

  1. GET /api/trips에서 ID를 선택하고 추천을 요청한다. 202는 등록 성공이다.
POST /api/media/jobs
Content-Type: application/json
{"tripId":"demo","profile":"STORY_15"}

→ 202 {"jobId":"…"}
GET /api/media/jobs/{jobId}

1~3초 간격으로 조회하고 화면 이탈·READY·FAILED 시 멈춘다. READY면 result.cards의 서버 순서를 사용한다. 각 카드의 title, recommendation.quote, recommendation.reason, cues를 표시한다. 예시 식별자 대신 실제 응답의 id를 사용한다. 카드의 시각은 모두 운행 시작 기준 ms다. 플레이어의 자막 시각은 (cue.startMs - card.startMs) / 1000초다.

GET /api/media/jobs/{jobId}/clips/{moment}
POST /api/media/jobs/{jobId}/edits
Content-Type: application/json
{"id":"moment-002","title":"다시 듣고 싶은 말"}

→ 202 {"jobId":"새 편집 작업 ID"}

편집은 제목·자막·구간 중 바꿀 필드만 보낸다. 제목은 1~80자, captions는 기존 발화와 같은 개수·순서의 문자열(각 200자 이하), startMs/endMs는 선택한 카드 안의 구간이다. 새 ID로 조회해 READY가 된 뒤 새 ID로 미리보기와 QR을 발급한다. 원본과 편집본은 다른 버전이다.

POST /api/media/jobs/{새 jobId}/clips/{moment}/handoffs
→ 201 {"id":"…","expiresAt":"…Z","qrImage":"data:image/png;base64,…"}

img.src = ticket.qrImage로 표시한다. 휴대폰 스캔 → 저장 확인 페이지 → ‘MP4 내려받기’ 순이다. 스캔만으로는 소진되지 않으며, 저장 요청 한 번에만 파일을 준다. 사용·만료·회수·다운로드 중단 후에는 재발급한다. 5분 만료, QR 이미지·코드는 로그에 기록하지 않는다. 카드 미리보기는 BFF에서 Range 요청과 206 응답을 그대로 전달한다.

4. 화면 상태와 복구

QUEUED → RUNNING → READY 또는 FAILED. READY여도 NO_SPEECH_CANDIDATE면 인식 발화 없음, NO_MEMORY_CANDIDATE면 선정된 구간 없음이다. 빈 카드를 오류로 표시하지 않는다. FAILED는 재시도 동작을 제공한다. 중복 작업은 같은 입력의 완성본을 재사용할 수 있다.

400 입력 수정 · 401 서버 토큰과 HTTPS 점검 · 403 탑승자/보호자/전사문 제공 등 해당 동의 확인 · 404 운행·카드·작업 다시 조회 · 409 정차/P단·도로 검토·기준 버전 확인 · 410 QR 재발급 · 416 Range 재요청 · 429 대기열이 비면 재시도 · 507 저장공간 확인. 작업 ID와 QR은 프로세스 메모리에 있어 서버 재시작 후 새 작업 요청이 필요하다. 작업 ID는 최근 최대 64개, 미사용 QR은 최대 128개다.

5. 기획 범위와 남은 작업

현재 서버는 사전 등록한 전·후방 영상과 원음을 읽고 추출 동의·P단·도로 검토를 확인한 뒤 한국어 전사 → Gemini 대화 추천 → 세로 영상·자막 생성 → 편집 → 휴대폰 저장을 처리한다. 글레오는 기획상 역할이고 실제 추천 모델은 Gemini다. 위험 구간 제외와 흐림은 제공된 구간표 기준이다.

실차 카메라 자동 수신·실제 탑승자 신원/동의 수집·자동 얼굴/번호판 검출·제품 원본 파기·개인별 보관함·SNS 작성기는 별도 과제다. 이 팀 작업공간에 실제 승객 음성이나 영상을 등록하지 않는다. QR 다운로드는 인스타그램이나 카카오톡 게시를 의미하지 않는다.
